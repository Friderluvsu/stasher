# Продукт

## Зачем

Stasher — настольное приложение для битмейкеров на FL Studio. У каждого со временем копятся сотни проектов `.flp`: в них лежат удачные мелодии, аккорды, басовые линии и барабанные паттерны, а также любимые семплы. Найти что-то из этого обычно значит открывать проекты по одному. Stasher сканирует папки с проектами, вынимает из них ноты и семплы, раскладывает по тегам и даёт утащить найденное мышью прямо в DAW. Всё работает локально и без интернета: данные лежат в SQLite-файле на компьютере пользователя.

Интерфейс двуязычный (русский по умолчанию и английский). Версия 1.0.6, сборки под macOS (Apple Silicon и Intel) и Windows (установщик NSIS).

## Что умеет

Четыре вкладки наверху окна.

**MIDI Паттерны.** Перетащите в окно `.flp` или папку — Stasher прочитает проекты и сохранит каждую партию (паттерн + канал) с нотами. Для партии считаются тег (Kick, 808, Chords, Melody и т. д. — по названию канала, семплу и нотам), длина в тактах, темп и тональность. Слева — фильтры по тегу и по проекту, вверху — поиск. Карточку можно утащить в FL Studio, Ableton, Logic и другие: приложение само создаёт `.mid` и начинает перетаскивание файла на уровне ОС. Октавы при этом переводятся в стандарт MIDI (см. [../architecture/flp-parsing.md](../architecture/flp-parsing.md)).

**StashSound.** Каталог семплов из тех же проектов: одношоты, 808, ударные, перкуссия, инструменты. Приложение находит файл семпла на диске по имени, определяет тип и тон (основная нота), даёт прослушать. Если файла на диске нет, играет встроенный образец подходящего типа.

**Визуализатор.** Превращает ноты (из FLP, MIDI-файла или хранилища) и/или аудио бита в анимацию 9:16 и записывает её в видео для Reels, Shorts и TikTok. Подробно — [visualizer.md](visualizer.md).

**Kit Builder.** Сборка набора: отметьте семплы и паттерны в двух других вкладках, добавьте их в именованный кит (можно несколько китов, активный выбирается), и экспортируйте ZIP — внутри папки по типам (808, кики, снейры, хэты, перкуссия, инструменты; для MIDI — мелодии и аккорды, барабаны).

## Принципы

1. **Всё локально.** Движок слушает только `127.0.0.1:8765`, данные лежат в одном файле SQLite, облака нет.
2. **Файлы пользователя не меняются.** Проекты читаются, но не пишутся. Если для разбора нужна поправленная копия (проекты FL 25 — см. разбор FLP), копия живёт во временной папке и удаляется сразу.
3. **Предпросмотр не засоряет хранилище.** Всё, что открыто в Визуализаторе, в базу не попадает: проект не добавляется, семплы на диске не ищутся.
4. **На картинке нет текста.** Видео из Визуализатора не содержит названий проектов, паттернов и файлов — его можно выкладывать, не выдавая лишнего.
5. **Картинка в предпросмотре и в видео одна и та же.** Один рендерер, одно правило времени (см. [../architecture/visualizer.md](../architecture/visualizer.md)).
6. **Сбой одного файла не ломает остальное.** Нечитаемый FLP даёт понятное сообщение, а не падение; если у проекта не удалось прочитать плейлист, остаётся «Луп».

## Откуда берутся данные

| Что | Откуда |
|---|---|
| Ноты, каналы, темп, ppq | `.flp` (через pyflp и собственный разбор событий) |
| Плейлист («Песня») | `.flp`, события плейлиста читаются напрямую (`backend/core/flp_playlist.py`) |
| Ноты MIDI-файла | `.mid`, `.midi`, `.kar` — читает сам интерфейс (`@tonejs/midi`) |
| Частоты звука | аудиофайл — разбирает сам интерфейс (БПФ в `src/services/audioAnalysis.ts`) |
| Семплы | файлы на диске, которые нашёл движок по имени из проекта |

## Для кого Визуализатор

Для битмейкера, который хочет за минуту сделать ролик к биту: бросил проект FL и готовый звук в окно, выбрал стиль и цвет, нажал «Экспортировать». Новичку не нужно знать ни про MIDI, ни про кодеки. Опытному пользователю доступны режим «Песня» (весь трек по плейлисту FL), выбор отдельных партий, длина ролика, разрешение и частота кадров.
